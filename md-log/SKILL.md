# md-log：会话 Markdown 镜像

## 开启（一次性）

1. 确定目标路径：
   - 用户指定了路径 → 用它
   - 否则默认 `<cwd>/.sessions/YYYY-MM-DD-HHMMSS.md`
2. `mkdir -p` 创建所在目录
3. 断点续写与防重：读取状态文件 `.sessions/.md-log-active`（内容 = 上次记录的日志绝对路径），并按目标文件现状判定：
   - 目标文件不存在或为空 → 全新开始：写入头部（步骤 4）
   - 目标文件已有内容 → 数出完整轮次数 N（每个以 `## 用户` 开头的标题连同其后 `## 助手` 小节计 1 轮）：
     - N ≥ 会话次数 → 已是最新（重复开启或恢复中断会话）：跳过 4–6，直接到 7 确认，不改动文件任何内容
     - N < 会话次数 → 断点续写：仅回填本次会话尚未写入的尾部轮次（步骤 5）
   - 状态文件指向其他路径 → 另一日志仍在记录：先按 md-unlog 结束它，再继续本流程
4. 写入头部（仅全新开始）：

   ```markdown
   # 会话日志

   - 开始时间: <YYYY-MM-DD HH:MM:SS>
   - 状态: 记录中
   ```

5. 回填缺失的尾部轮次（仅断点续写时）：把本次会话未写入的轮次按顺序补写，开头加一行 `<!-- 历史记录为开启日志时回填 -->`（仅在确有回填时）。若文件末节不是以 `## 助手` 开头的非空小节结尾（上次写入中断）→ 先截断到最后一个完整轮次再回填。完成标准：文件以 `## 用户` 开头的标题数 == 会话次数，且各轮内容与对话一致；不相等则继续补齐。回填轮次同样按每轮格式带标题摘要。文件已有轮次保持原样。
6. 写状态文件 `.sessions/.md-log-active`（内容 = 日志文件的绝对路径），md-unlog 靠它定位
7. 若在 git 仓库内且 `.sessions/` 未被忽略 → 向 `.gitignore` 追加一行 `.sessions/`（避免状态文件被提交）
8. 确认成功：整轮回复只含一行 `link: <日志文件绝对路径>`（例：`link: /Users/me/proj/.sessions/2026-01-01-120000.md`），不得附带回填轮次数或其他说明，本轮对话不用写入

## 每轮（循环）

**先写后答**：回复正文发出前，日志文件末尾必须已有本轮记录。检查：`tail` 日志文件，确认末节是刚写的本轮内容。

每轮追加格式：

```markdown
---

## 用户：<摘要，≤10 字>

<用户消息>

## 助手：<摘要，≤10 字>

<助手最终回复正文（不含思考过程）>
```

标题摘要须 ≤10 字且不得为空：用户摘要取自该条用户消息的要点，助手摘要取自该条回复正文的要点。

记录范围：

- 用户消息与助手文本回复逐条记录，用户消息尽量原文
- 助手只记录最终回复的正文内容，不记录思考过程（内部推理）
- 工具调用不逐条记录，重要结果并入该轮「助手」小节用一句话说明
- 过长代码块可截断并注明 `(已截断)`
- 始终续写（追加到文件末尾），保留全部既有内容
